# 技術調査: JIZURA(字面) と LyricFlow の比較・取り込み方針

調査日: 2026-09-24 / 対象: https://852wa.github.io/JIZURA/ (GitHub `852wa/JIZURA`, MIT License, © hakoniwa)
方法: リポジトリを取得し、コア(`src/01〜12`)・演出パック(`src/11p_*`)・書き出し(`src/11_export.js`)・After Effects連携(`ae/`, `cep/`)を
サブシステムごとに精読。本書は設計の要点を散文でまとめたもの(コードは転載していない)。
LyricFlow 側の実装は本調査を参考にした**独自実装**(`static/js/compose/`)。

## 1. JIZURA の全体像

- **ブラウザ完結の無料ツール**(GitHub Pages の静的サイト。ログイン・サーバー無し。保存/読込はローカルファイル)。
- 歌詞 → 「カット」に分割 → カットごとに **構図(layout) + 登場(enter) + 保持(hold) + 退場(exit) + 装飾(decor) + 文字加工(treat) + 背景(bg) + カメラ(cam) + 画面fx + つなぎ(trans)** を割り当て、Canvas2D に描く。
- 全てシードから決定論的に決まる(同じ時刻 → 同じ絵)。描画時に `Math.random` を使わず、ハッシュ関数を時刻・字番号・24Hz クロックで引く。
- 演出は**レジストリ**にパック単位で登録(1ファイル=1パック、コアは触らない)。メタデータ(雰囲気タグ・重み・字数の適合・縦長倍率・強調倍率)で汎用の重み付き抽選を回す。
- **色ずれゴースト**: 1フレームを「時間を少し遅らせた単色パス×2 + 本描画」の3回描き、動く文字に色の残像が出る(シグネチャの見た目)。

### 重要な設計判断
1. **構図と動きの分離**: 構図は「どこに・どの大きさで・何の上に置くか」だけを決め、歌詞本体は必ず共通の描画口を通る → どの構図もどの登場/退場とも組み合わさる。
2. **計画と描画の分離**: `plan(rng)` で乱数を全て素の JSON パラメータに解決し、`render` はパラメータ・時刻・パスだけの純関数。
3. **スタイルは重みを「置き換える」**: スタイルの bias 表が各演出の抽選重みを直接上書きし、世界観を一貫させる。
4. **色は常にコントラスト判定で選ぶ**(固定色を持たない)→ どの配色でも成立。
5. **モーションの「スライド窓式スタッガー」**: 字ごとの進行度を `(p − spread×順番)/(1 − spread)` で作るので、全字が p=1 で必ず揃う。退場の終端は強制的に不可視。
6. **おまかせ**: 雰囲気→(72%で)合うスタイル→スライダー値→有効パーツ→新しい種、を一括で振り直す。◀/▶ で最大80案の履歴、「ここだけ変える」で配色/雰囲気/構成だけ振り直し、行ごとの 🎲・🔒。
7. **歌詞記法**: `/` カット分割、`*強調*`、行末 `!` 衝撃、`文|注釈`、LRC 時刻。空行で2拍の間。
8. **書き出し**: ブラウザ内 WebCodecs(H.264→VP9→AV1 フォールバック)+ mp4-muxer、7アスペクト、720p〜4K、24/30/60fps、グリーン/ブラックバック。
9. **AE書き出し**: 「計画 JSON」を出力し、AE 側の約3万行の ExtendScript が全演出をネイティブ(テキストアニメーター+エクスプレッション、シェイプ、プリコンプ)で再構築。README 上は実機 AE での検証は未実施(モック AE でのテストのみ)。

## 3. 取り込んだもの(今回の実装)

- **演出エンジン(カット演出)** `static/js/compose/`: 構図/登場/保持/退場/装飾/加工/カメラ/つなぎ/配色スタイル のレジストリ、テキスト項目モデル(字ごとの関数・クリップ・帯・残像・押し出し・柄)、色ずれゴースト3パス、決定論ハッシュ、スライド窓スタッガー、つなぎの A/B 合成。
- **演出の数: 442種**(構図156・登場77・保持29・退場57・装飾46・文字加工23・カメラ17・つなぎ17・配色スタイル20)。
  従来の31アニメ・24画面エフェクト・16レタリングもそのまま使える。
  全種を 16:9/9:16/1:1 × 5種の歌詞(1字〜16字・欧文)× 複数時刻でスモークテスト(エラー0)、
  登場の終端=静止/退場の開始=静止の連続性を自動検査、点滅系は1秒3回以下(光過敏対策)。
- **おまかせ(R キー)・◀前の案/次の案▶・ここだけ変える(配色/構図/動き/装飾/カメラ)・カットごとの編集・🎲振り直し・🔒固定・タイムラインの演出トラック**。
- **歌詞記法**: `*強調*` / 行末 `!` / `文|注釈` / `/` 分割。長い行は「カット密度」に応じて語の区切りで自動分割、BPM があれば拍へ 0.13 秒以内でスナップ。
- **フォント**: 役割フォント(主役/強調/補助)、ムードタグ・推奨の動き・日本語対応フィルタ付きの「フォント見本」(実際の歌詞を動かして比較)、おすすめの組み合わせ。
- **書き出し**: グリーンバック/ブラックバック(合成用)、24fps。
- **After Effects 用書き出し(.jsx)**: コンポ・グラデ背景・(任意で)曲・カットごとの編集可能なテキストレイヤー(登場/退場をキーフレーム化)・マーカー・グロー調整レイヤー。構図は簡略化(中央配置)。

## 4. 取り込まなかった/今後の候補

- ブラウザ内 WebCodecs 書き出し(サーバーへの JPEG 送信を省けて速い)。
- AE への**全演出の忠実な再構築**(今回は編集可能なテキスト+基本モーションの簡略版)。
- 背景グループ(JIZURA の手続き的背景)と、カット境界を覆う画面fx。LyricFlow は独自の背景シーン・画像背景・画面エフェクトを使う。
- 繁体/簡体中文・韓国語の歌詞に合わせた役割フォントの自動切替。
- 曲頭のタイトルカード、間奏用カット。
